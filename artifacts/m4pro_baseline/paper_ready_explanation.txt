Paper-Ready Baseline Description

We established a reproducible long-context inference baseline for llama.cpp on Apple M4 Pro hardware using the Metal backend. The objective of this baseline was to provide a stable reference point for subsequent experiments on KV cache policy design under Apple unified-memory constraints.

Experimental Setup. We used the official ggml-org/llama.cpp implementation and built it locally with CMake in a dedicated Metal-enabled build directory. Inference was executed with GPU offload enabled so that the Apple GPU and unified memory subsystem were actively involved in model execution. The tested model was Llama 3.1 8B Instruct in GGUF format with Q4_K_M quantization. The exact repository revision, build commands, model download command, model checksum, and inference commands are recorded in baseline_m4pro.csv.

Prompt and Measurement Protocol. To ensure comparability across context lengths, we used a deterministic fixed-prompt construction rather than a free-form natural-language prompt. For each target context length, the prompt was synthesized to occupy the context up to a reserved decode budget of 256 generated tokens. This design ensured that each run measured behavior under near-full-context conditions instead of merely allocating a larger KV cache without filling it. Decode throughput was measured in tokens per second, and time to first token was derived from the logged prompt-evaluation and sampling timings. Raw execution logs and prompt files were preserved as artifacts for auditability and reruns.

Measured Context Lengths. We collected baseline measurements at context lengths of 4096, 8192, 16384, and 32768 tokens. Across these runs, the Metal runtime logs confirmed that inference was executing on the Apple M4 Pro GPU, that unified memory was available, and that all transformer layers were offloaded to the GPU.

Observed Stability Boundary. In addition to the fixed benchmark points, we probed the upper stable context limit for this configuration. Under the tested setup, inference remained stable through 196608 tokens. At 197632 tokens, the Metal backend produced an out-of-memory failure. We therefore report 196608 tokens as the maximum stable context length observed for this specific combination of hardware, llama.cpp revision, model format, quantization, and runtime configuration.

Interpretation. These results should be understood as a configuration-specific baseline rather than a universal limit of Apple M4 Pro hardware. The effective context ceiling and throughput characteristics may vary with future llama.cpp revisions, different quantization schemes, KV cache representations, flash-attention behavior, background memory pressure, and operating system state. Nevertheless, this baseline provides a concrete and reproducible reference for evaluating the impact of alternative KV cache policies on long-context inference performance in unified-memory environments.
