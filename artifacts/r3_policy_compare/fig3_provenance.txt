Figure 3 — provenance change and what the figure now says
=========================================================
2026-08-04. Regenerated by scripts/make_figures_final.py.
Addresses review items M1, DA-3, P7, C2.

WHY THE OLD FIGURE-3 ARM WAS RE-RUN
-----------------------------------
The candidate policy-1 datum on disk was stress_results/stress_policy_1024_e2e.csv
(2048 tokens at 40.002 tok/s). Its own run log settles the protocol question:

  artifacts/stress_benchmark/logs/stress_policy_ctx1024.log
    llama_context: n_ctx         = 1024
    llama_context: n_batch       = 512
    llama_context: n_ubatch      = 512
    llama_context: flash_attn    = enabled      <-- FLASH ATTENTION ON

while both arms of stress_results/r2_policy_compare.csv ran with it off:

  artifacts/r2_policy3/logs/gen_r1_p0_c1024.txt : flash_attn = disabled
  artifacts/r2_policy3/logs/gen_r1_p3_c1024.txt : flash_attn = disabled

So the arms did NOT match: putting 40.0 tok/s beside the flash-attention-off
p0/p3 numbers would have folded the flash-attention penalty (separately measured
at 12.4% at C=4096, artifacts/r2_policy3/fa_penalty_analysis.txt) into the
policy comparison. It was also a different harness (run_stress_benchmark.py,
which hardcodes -fa on) and a policy-1-era run predating the spill-recall work.
Re-run under the matched protocol, policy 1 at C=1024 with flash attention off
gives 37.83 tok/s (single check run) and 38.64 +/- 0.03 (cooled block, n=3).

NEW PROVENANCE — all three M4 bars from ONE cooled flash-attention-off block
---------------------------------------------------------------------------
  bar                     value  source
  M4 Pro baseline           512  r3_policy_compare_cooled_master.csv, arm p0_c1024
  A100 baseline             511  a100_benchmark(server version)/baseline_a100.csv,
                                 ctx=1024 -> generated_tokens_reported
  M4 Pro rolling window    2048  r3_policy_compare_cooled_master.csv, arm p1_c1024
  M4 Pro UniKV             2048  r3_policy_compare_cooled_master.csv, arm p3_c1024

make_figures_final.py now asserts, per arm, that every trial decoded exactly the
locked count AND that every trial reports flash_attn = disabled, dying with the
CSV name on any mismatch. The A100 511 is no longer hardcoded — it is read from
baseline_a100.csv. (That A100 run is flash-attention ON, as its own CSV records;
this is a token COUNT, which is independent of the attention kernel, but it
should be stated rather than glossed.)

Superseded sources: stress_baseline_1024.csv (row count) and
stress_policy_1024.csv (row count) are no longer used for this figure.

WHAT CHANGED IN THE FIGURE ITSELF
---------------------------------
1. A fourth bar: the policy-1 rolling window, at 2048 tokens.
2. The "~4x more tokens generated" callout is REMOVED. With policy 1 present
   the 4x is visibly a statement about the baseline's error path, not about
   UniKV: against the continuation policy the same codebase ships, the token
   counts tie. Keeping the callout next to a tied bar would have been the
   cherry-pick DA-3 names.
3. A dashed "decode budget" line at 2048 and a "halts at cache-full" label on
   the two baseline bars, so the figure's claim is completes-vs-halts (P7's
   point: 2048/512 is the ratio of a chosen budget to a chosen C — an 4096-token
   budget would have read "8x").

*** ACTION REQUIRED IN THE PROSE (not done here — main.tex is untouched) ***
The Figure-3 caption and every "4x" in the abstract, introduction, contribution
list, Section 5.2 and the conclusion still describe the three-bar figure. The
figure no longer supports "4x more tokens" as a UniKV property. The measured
replacement claim is: the baseline halts at 512 of 2048 tokens (511 on A100 —
the same upstream error path), while both continuation policies complete the
budget; the difference between them is not how many tokens but which context
survives (see quality_results/quality_arms_unified.csv), at a measured cost of
25.2% throughput at C=1024 (38.64 -> 28.90 tok/s).
